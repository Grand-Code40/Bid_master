# Bid_master: актуальная панель Sites, v26

Публичный исходный код панели из версии v26. Это отдельная Worker/D1-реализация в каталоге `sites-panel/`; исходная Python-реализация в корне репозитория сохранена без изменений. Существующая ветка `feat/send-inbox-v23` не изменяется.

## Что включено

- Интерфейс заказов, редактор отклика, кнопка копирования и открытия площадки.
- Жизненный цикл заказа, история отправленного и журнал наблюдений с защитой от повторной отправки.
- Сохранённые email-уведомления, пагинация и ссылки на соответствующие переписки.
- Owner-scoped API/MCP, проверка URL, CAS и идемпотентные операции.
- Код Worker, исходники интерфейса, декларативная схема, четыре Drizzle-миграции и тесты.

Панель сама не отправляет отклики на площадки. Sender-компонент не подключён к HTTP/MCP; очередь и копирование текста не доказывают отправку. Входящие содержат ранее сохранённые наблюдения, а не полный синхронизированный inbox площадок.

## Локальная проверка

Требуется Node.js 22.13+ или более новый релиз с модулем `node:sqlite`.

```sh
cd sites-panel
node scripts/build-local.mjs
node --check build/worker.mjs
node --test
USE_GENERATED_MIGRATIONS=1 node --test
```

Эти команды не требуют установки npm-зависимостей и используют только синтетические данные в изолированной SQLite в памяти. Drizzle-зависимости закреплены в `package-lock.json` и нужны для изменения/генерации схемы, а не для исполнения Worker или этих тестов. Адаптер тестов не является эмулятором hosted D1.

`npm run dev` предназначен только для изолированного управляемого QA-контейнера и требует `SITES_MANAGED_LINUX_CONTAINER=1`. Preview подставляет искусственного владельца и привязан к `0.0.0.0`; нельзя открывать его в общей сети или использовать с реальными данными.

## Конфигурация и безопасность

- В публичной копии нет ID развёрнутого Site, owner ID, runtime-переменных, токенов, cookie, аккаунт-сессий или базы.
- Шаблон `.openai/hosting.example.json` содержит только структуру привязки `DB`. Локальный `.openai/hosting.json` исключён из Git. Для новой установки его настраивают отдельно; действующих идентификаторов в шаблоне нет.
- `OWNER_USER_ID` задаётся безопасно в runtime. Опциональный `WRITER_TOKEN` имеет минимум 32 символа и не хранится в исходном коде.
- Доверять `oai-authenticated-user-id` можно только за аутентифицированным gateway Sites. Нельзя публиковать этот Worker напрямую на незащищённом hostname или proxy: клиент смог бы подделать заголовок.
- Публикация исходников не развёртывает и не обновляет работающий Site, не переносит базу и не меняет настройки аккаунтов.

См. [HANDOFF.md](HANDOFF.md) для точного состава snapshot и границ переноса.
