## Происхождение

- Версия исходника: Sites v26.
- Исходный commit: `fcb1cb26adc06f835bee331ea4a31e12f0c7d756`.
- GitHub-база: Python `main`, commit `4856ee5472780e83069653d6d71e0801685b8fea`.
- Публикация добавляет только каталог `sites-panel/` на отдельной ветке. Python-код и история `main` не заменяются; private-история Site не импортируется.

## Изменения только для публичной копии

1. Runtime hosting manifest заменён шаблоном без ID Site. Реальный manifest, `.env`, базы, сессии, generated build, логи и зависимости не включены.
2. Статический снимок настроек почты конкретного владельца в `web/index.html` заменён нейтральным «Не настроено в публичной копии». Два соответствующих теста проверяют этот публичный вариант. Логика интерфейса, API и схемы не менялась.
3. Приватные эксплуатационные заметки и старые deployment-отчёты не включены. Вместо них добавлены этот handoff и актуальный README.
4. Все остальные включённые исходники и миграции скопированы из указанного commit без изменений. Публичные URL площадок и явно синтетические тестовые адреса оставлены; реальные письма, отклики и аккаунт-настройки не публикуются.

## Работа с существующей установкой

Не направлять новую копию на production DB и не выполнять миграции/деплой только потому, что исходники появились в GitHub. Сначала сверить текущую версию и настройки существующей установки, затем использовать поддерживаемую цепочку подготовки и развёртывания. Не создавать вторую очередь отправки и не переносить реальные записи из тестов.

`drizzle/` содержит только определения схемы и schema metadata, без seed-данных. Тесты проверяют поведение на SQLite в памяти с fixture SQL и с generated migrations. Они не заменяют hosted auth/D1 и browser QA. Публикация snapshot не выполняет внешний сбор, отправку сообщений, изменение аккаунтов или production-запись.
