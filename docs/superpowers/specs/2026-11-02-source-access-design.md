# Bid_master: доступ к источникам и первичный сбор CAD-заказов

Дата: 2026-11-02. Статус: согласовано владельцем 2026-11-02; первый этап реализован и проверен; UI и отправка откликов остаются следующими этапами.

## Задача и принятые требования

Первым этапом владелец хочет проверить самую неопределённую часть: доступ к площадкам, регистрацию и чтение объявлений. Будущая система должна находить CAD-заказы на российских и зарубежных площадках и в интернете, обновлять сведения каждые 30–60 минут и показывать их в контрольном центре. Отклики отправляются после одобрения владельцем, ответы возвращаются в тот же центр.

Владелец подтвердил следующие решения:

- Использовать браузер, в том числе авторизованную сессию, если API не хватает.
- Максимально автоматизировать заполнение регистрационных форм; повторно не просить уже предоставленные сведения.
- Искать широкий набор CAD-задач, включая сложные 3D-задачи. Выполнимость определяет владелец.
- Первоначально собирать статистику спроса; опубликованный бюджет не считать фактической оплатой.
- В дальнейшем предлагать низкую предварительную цену и конкретный результат. Окончательные условия определяет владелец.
- Не добавлять планирование загрузки и резервирование рабочего времени.
- Учитывать объявления с требованиями конфиденциальности в статистике, не передавая их закрытые файлы внешним инструментам.
- Тяжёлые данные, профили браузера, временные файлы и результаты проверок размещать только в D:\DrawingAI_runs\<задача-дата>.

Отсутствие аккаунта не должно мешать чтению публичного источника. Создание аккаунта, успешный вход, доступ к объявлениям и право отправлять отклики — разные состояния.

## Подходы

1. Только API и ленты: проще поддерживать, но исключает сайты без подходящей интеграции. Для запроса владельца недостаточно.
2. Только браузерный агент: соответствует предложенному владельцем способу доступа, но каждый обход зависит от состояния интерфейса и сессии.
3. Гибрид: API/лента или HTTP для доступных данных, управляемый браузер для остальных страниц и подключения аккаунтов. Это предлагаемая реализация выбранного владельцем приоритета — поддержать браузерный доступ. Выбор конкретных библиотек остаётся за исполнителем.

Рекомендуется третий подход. Не обещается исчерпывающее покрытие интернета либо отсутствие блокировок на любом сайте.

## Минимальный результат первого этапа

Один вертикальный проход: чтение реального публичного CAD-источника → структурированные объявления → постоянное хранение → повторный обход с обновлением записей → обзор состояния источников и статистики. Параллельно — управляемое подключение аккаунтов с остановкой только там, где требуется участие владельца.

Первый подтверждённый источник — FL.ru: публичная лента и раздел «Инжиниринг». Второй вход — ручное добавление URL объявления поддерживаемого источника. Freelance.ru и Telegram входят в очередь проверки, но не считаются подключёнными до реальной проверки доступа и извлечения данных. Kwork остаётся кандидатом: его текущие правила ограничивают автоматический сбор; регистрация аккаунта сама по себе это ограничение не снимает.

В первом этапе нет отправки откликов, переписки, выполнения CAD-заказов и полной визуальной панели. Для проверки достаточно консольной команды и читаемого отчёта. Данные и интерфейсы проектируются для последующей панели; её встраивание не блокирует сборщик.

## Компоненты

### Реестр источников

Для источника хранить стабильный идентификатор, название, корневой URL, разделы/поисковые запросы, метод доступа, возможности чтения списка/деталей/бюджета/числа откликов, время успешного обхода и текущую причину недоступности. Непроверенное поле или возможность остаётся неизвестным, а не объявляется работающим.

Различать состояния: не проверен, публично доступен, нужен вход, нужна проверка владельцем, доступен после входа, ограничен, временная ошибка. При ошибке одного источника остальные продолжают работать. Ограниченные повторы и задержки не должны превращать заблокированный источник в бесконечный цикл.

### Подключение аккаунта

Общий профиль содержит предоставленные владельцем имя/публичное название, email, страну, город и описание услуг. Пароли, коды и содержимое сессии не попадают в репозиторий и отчёты. Секреты хранить через подходящий защищённый механизм ОС или браузера; конкретный механизм выбирает исполнитель. Не извлекать скрыто пароли или cookies из чужих профилей.

Публичные имена, выбранные владельцем: основной бренд — **CAIgraph**; альтернативное имя для российских площадок — **Константин Аистов**, для иностранных — **Casei**. Это варианты публичного представления, не подтверждённые юридические имена и не основание создавать несколько аккаунтов одного пользователя. При запросе юридического имени, страны или города не угадывать значения. Владелец сообщил, что телефон для подтверждений есть; сам номер запрашивается только при необходимости. Рабочий email предоставлен в чате, его авторизованная Gmail-сессия проверена; адрес и содержимое ящика не дублируются в репозитории.

Порядок: проверить наличие существующего аккаунта → открыть фактическую форму → заполнить известные данные → показать только недостающий шаг → завершить допустимые шаги после необходимых подтверждений → проверить признак выполненного входа → проверить доступные возможности. Не считать отправленную форму успешной регистрацией.

Уже имеющиеся аккаунты подключать вместо создания дубликатов. Дополнительные аккаунты допустимы только для разрешённых площадкой реальных отдельных профилей/команды; не создавать вымышленные личности, аккаунты для обхода блокировки или квот. Для Kwork использовать один аккаунт пользователя согласно текущим правилам.

Самого адреса email недостаточно для подтверждений: нужен разрешённый доступ к рабочему почтовому ящику либо действие владельца. Доступ к почте ограничить письмами регистрации и подтверждения выбранных сервисов. Телефонные коды и проверки личности обрабатывать через соответствующий пользовательский шаг; не загружать документы без отдельного конкретного разрешения. При текущем Browser Use принятие обязательных условий и CAPTCHA требуют подтверждения в момент действия. Кнопка «Подключить» в будущем не должна обещать обход любых проверок.

### Чтение и нормализация

Общая запись: источник, внешний идентификатор или канонический URL, заголовок, исходное описание, ссылка, вид публикации, категории CAD, опубликованный бюджет с валютой/единицей расчёта, число откликов при наличии, время публикации при наличии, первое и последнее наблюдение, доступность/закрытие, требуемые форматы, явно указанные ограничения.

Неизвестные значения хранить как неизвестные. Не подставлять ноль вместо скрытой цены или числа откликов. Сохранять происхождение каждого извлечённого значения и время наблюдения. Не смешивать разовый заказ, зарплату в вакансии и призовой фонд конкурса.

Точная уникальность — источник плюс внешний идентификатор/URL. Похожие объявления разных источников помечать как возможные дубли без необратимого автоматического объединения. Повторный обход обновляет бюджет, описание, число ответов и статус; факт просмотра не запрещает дальнейшую обработку. Старую логику `reserve_project` в AutoBid не использовать как универсальный признак завершённой обработки.

Сбор текста и полей выполняется детерминированными средствами, где это возможно. ИИ необязателен для первого прохода. Возможность передачи содержимого источника модели оценивается отдельно от технической доступности страницы. В частности, публичность Telegram-страницы не отменяет его условий использования контента.

### Обход интернета

Список источников расширяется через обнаружение релевантных сайтов и страниц поиском, затем проверку найденного источника и добавление его адаптера/конфигурации. Произвольный URL не считается автоматически поддерживаемым. Для первого этапа достаточно реестра и ручного добавления URL; постоянно работающий поисковый провайдер подключается позже по отдельной конфигурации и бюджету.

### Запуск и хранение

Сохранить существующий Python-проект. Сборщик отделить от сервиса отправки ставок. Локальная SQLite подходит первому одиночному исполнителю; не требуется менять уже существующую схему AutoBid разрушительными миграциями. Файлы базы, профили браузера и отчёты направлять на D:.

Сначала обеспечить конечную команду одного обхода. Для автономных повторов предусмотреть локальный планировщик и блокировку перекрывающихся запусков; по умолчанию предлагается интервал 60 минут. Запуск расписания — отдельное явное действие владельца. Компьютер должен оставаться включённым. Сессия текущего ChatGPT-браузера служит проверкой доступности, но сама по себе не является программным интерфейсом для фонового Python-процесса. Поддерживаемый браузерный runtime и переносимый способ пользовательского входа должны быть выбраны и проверены при реализации; не обещать перенос cookies из ChatGPT.

Для первого этапа не требуется покупать VPS, прокси или платные подписки. Если выбранному способу доступа нужен платный сервис, сначала показать конкретный сервис и стоимость владельцу. Встроенный мониторинг не должен незаметно включать отправку сообщений или платные операции.

## Проверка результата

- Реально прочитаны список и детали нескольких CAD-объявлений FL.ru; извлечённые поля сопоставлены с видимой страницей.
- Повторный обход обновляет запись и не создаёт дубликат.
- Отсутствующий бюджет/счётчик и закрытый заказ представлены корректно.
- Нуждающийся во входе источник не останавливает доступные источники.
- Подключение аккаунта сохраняет достигнутый шаг и возобновляется после участия владельца.
- Запуск публичного чтения не требует аккаунта и не отправляет отклики.
- В журнале нет паролей/кодов; результаты и временные данные находятся на D:.
- Существующие 39 тестов AutoBid продолжают проходить; дополнительные тесты проверяют границы нового процесса, а не имитируют реализацию построчно.

## Что требуется от владельца

Рабочий email предоставлен, доступ к почте через авторизованный браузер проверен, публичные имена выбраны. Телефон для подтверждений у владельца есть. Страну, город и другие недостающие сведения запрашивать только при наличии соответствующего обязательного поля конкретной площадки. Перед созданием аккаунта проверять наличие существующего; отсутствие писем в почте само по себе не доказывает отсутствие аккаунта. Портфолио и описание профиля нужны при переходе к продаже услуг, но не блокируют публичный сбор. Пароли, коды и документы не отправлять в этот файл или чат; постоянное хранение новых паролей требует отдельно выбранного защищённого хранилища, которого пока не настроено.

Владелец подтвердил границы этого этапа: гибридный доступ, первый источник FL.ru, подключения остальных по мере проверки, без отправки откликов и без полного UI. Данные владельца не нужны для разработки публичного чтения.
