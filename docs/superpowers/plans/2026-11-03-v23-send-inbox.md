# v23 Sending and Inbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Implement owner-approved delivery orchestration and an honest unified Inbox in the supplied sanitized v23 derivative.

**Architecture:** Retain Worker/D1 and existing owner/writer boundaries. A trusted `SENDER_SERVICE` binding supplies actual platform inspection/submit/readback; absent binding disables delivery. Gmail uses fixed official REST endpoints and server-only OAuth configuration. Preserve legacy records and add only new tables/indexes.

**Tech Stack:** JavaScript ESM, Worker fetch/service binding, D1 SQLite, Node 24 synthetic tests and offline guard.

**Spec:** `panel/docs/SEND_INBOX_DESIGN.md`, approved by owner in chat 2026-11-03.

## Global Constraints

- No production deployment/migration, real sends, profile/session changes, or private data in GitHub.
- All artifacts/worktrees/temp files on D:; public code under panel/; historical Python main remains separate.
- Weblancer paused; archived Freelancer/Kwork/Freelancehunt stay archived.
- Exact owner-approved snapshot, one submit attempt, unknown outcomes blocked, recovery is read-only.
- Preserve old operation hashes, event history, delivery guards and mail bytes.

## Review Focus

- Concurrent identical requests return the same result/attempt, never a second submit.
- Crash or storage failure after external submission leaves a durable blocked attempt.
- Old disabled-sender confirmations cannot authorize a newly connected sender.
- New message import with old provider date is reachable by explicit timeline traversal; partial sync is visible.
- Provider/account/config changes never reuse another account's cursor or expose secrets.

Interfaces: senderStatus(env), preflightDelivery(db,owner,args,env,now), sendDelivery(db,owner,args,env,now), recoverDelivery(db,owner,args,env,now).
Binding contract: fetch internal HTTPS paths /inspect, /submit, /readback; server-fixed paths, no arbitrary URL. Strict response schemas. Snapshot fields match existing delivery_confirmation; new opaque preflight ID plus transport revision bind fresh approval. Immutable attempt precedes external side effect. Readback must match full snapshot and own published response ID; missing/ambiguous becomes uncertain, no automatic not_sent on absence.
