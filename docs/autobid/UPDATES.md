# Обновления при совместной работе Windows и облачного агента

GitHub хранит общий код. Рабочая база заказов, черновики, очередь, cookies, браузерные профили и настройки остаются в постоянном DISCOVERY_DATA_ROOT каждого компьютера. Git не синхронизирует эти данные. Для рабочей очереди нужен один выбранный центр и один отправляющий агент.

## Как получать изменения

1. Записать текущую ветку и commit; проверить локальные изменения:
   ```bash
   git status --short --branch
   git rev-parse HEAD
   git fetch origin
   ```
2. Если рабочая копия чистая, находится на main и не содержит собственных неопубликованных коммитов:
   ```bash
   git diff --stat HEAD..origin/main
   git merge --ff-only origin/main
   ```
3. Если агент уже меняет код, сохранить свою работу в отдельной ветке и коммите (без секретов и файлов базы). Затем объединить origin/main с этой веткой, разрешить пересечения и проверить результат. Не использовать reset --hard, git clean или force push, чтобы получить обновление. Если ветки разошлись, не обходить отказ fast-forward принудительной заменой.
4. Собственные изменения публиковать отдельной веткой и pull request в main. Перед объединением снова получать origin/main. Указывать владельцу итоговый SHA, способ проверки и нужно ли перезапускать приложение.

Изменения облачного агента, которые ещё не опубликованы, не видны локальному разработчику. Разные ветки и небольшие обновления уменьшают риск перезаписи; пересечения в одних файлах требуют обычного объединения кода.

## Обновление окна отклика, 2 ноября 2026

В каждой строке одна кнопка «Ответить». Она открывает модальное окно с описанием и откликом. Закрытие — кнопка, Escape или фон; несохранённый текст защищён подтверждением.

Изменены статические HTML/CSS/JS, проверка интерфейса и документация. Backend, формат импорта, CLI агента, API, база и состояния очереди совместимы с предыдущей версией. Миграция данных не нужна.

При запуске штатного сервера прямо из обновлённой рабочей копии достаточно перезагрузить страницу: сервер читает статические файлы при запросе. Сначала сохранить правки открытого отклика. Если приложение установлено из пакета или развёрнуто отдельной сборкой, обновить именно эту установленную копию/сборку; одного git fetch недостаточно. Для этой правки перезапуск штатного сервера и отправляющего агента не требуется.

Публикация в GitHub не означает, что облачный агент уже загрузил или применил обновление. Это нужно подтвердить отдельно по SHA и видимому интерфейсу.

Прочитай docs/autobid/UPDATES.md, получи обновление, сохрани свои текущие изменения и объедини их при необходимости. Сохрани рабочий DISCOVERY_DATA_ROOT, базу, очередь и сессии площадок.
